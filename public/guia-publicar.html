La web ya tiene servidor y base de datos. Estos son los pasos para abrirla hoy y compartirla por internet después.

AHORA · EN TU EQUIPO

Ábrela con dos clics.

En esta carpeta, haz doble clic en ABRIR XPEDITION.cmd. Se inicia el servidor y se abre el navegador. Si ya está funcionando, usa este botón:

Abrir The Xpedition ↗

Crea tu cuenta desde «Únete al universo». Para comprobar el chat, crea otra cuenta en una ventana privada y escríbele desde Comunidad. localhost solo funciona en tu propio equipo.

01 · PREPARAR LOS ARCHIVOS

Guarda el proyecto en GitHub.

  1. Entra a crear repositorio en GitHub y ponle, por ejemplo, the-xpedition-universe. Puedes hacerlo privado.
  2. Sube el contenido de esta carpeta al repositorio. En la raíz deben quedar server.mjs, package.json, Dockerfile, render.yaml y la carpeta public.
  3. No subas la carpeta data. Ahí están las cuentas y conversaciones privadas. El archivo .gitignore ya la excluye si usas Git.
  4. Si subir tantos archivos desde el navegador es incómodo, usa GitHub Desktop: File → Add local repository → elige esta carpeta; si no es un repositorio, crea uno aquí. Revisa los archivos, crea el commit y pulsa Publish repository.
02 · DARLE UN HOGAR

Crea el servidor en Render.

Esta es una ruta preparada en los archivos del proyecto. El servicio con disco persistente puede generar cargos; revisa el costo en Render antes de confirmar.

  1. Entra a Render y conecta el repositorio que creaste en GitHub.
  2. Elige New → Blueprint, selecciona el repositorio y deja que lea render.yaml.
  3. La plantilla propone un servicio Node.js 24 y un disco de 1 GB en /var/data. El disco es lo que conserva tus mensajes y archivos al reiniciar.
  4. En PUBLIC_URL escribe temporalmente https://pendiente.invalid si aún no se conoce la dirección. Despliega y copia la URL real que Render asigne al servicio. Durante este paso todavía no intentes registrarte.
  5. En el panel del servicio ve a Environment, cambia PUBLIC_URL por la dirección real, por ejemplo https://the-xpedition-universe-abcd.onrender.com, sin barra final. Guarda y espera la actualización.
  6. Comprueba que SECURE_COOKIES=true, DATA_DIR=/var/data y HOST=0.0.0.0. El archivo de configuración ya los define.
En Render, un sistema de archivos sin disco persistente se pierde al reiniciar o desplegar. Mantén el disco conectado. Usa una sola instancia para esta versión con SQLite.
03 · CONECTAR GOOGLE

Autoriza tu nueva dirección.

  1. Abre Firebase → The Xpedition → Authentication con la cuenta propietaria del proyecto.
  2. En Sign-in method, comprueba que Google esté activado y tenga un correo de soporte.
  3. En Settings → Authorized domains, pulsa Add domain y añade solo el dominio del hosting, como the-xpedition-universe-abcd.onrender.com. Sin https:// ni rutas.
  4. Si luego compras un dominio propio, añádelo también aquí y actualiza PUBLIC_URL en Render.
  5. Abre tu web pública, pulsa Continuar con Google y completa tú el selector de cuenta. Si el navegador bloquea la ventana, permite ventanas emergentes para tu web.

No hace falta poner contraseñas ni claves privadas de administrador en el HTML.

04 · EL PRIMER ENCUENTRO

Prueba y comparte tu enlace.

  1. Crea dos cuentas desde navegadores o dispositivos distintos.
  2. Comprueba el perfil, el selector de personajes y el botón Seguir.
  3. Abre un chat desde Comunidad, envía un texto y responde desde la otra cuenta. Prueba una imagen y un grupo.
  4. Recarga la página: el historial debe seguir ahí.
  5. Comparte la URL pública de Render con tus participantes. Ellos crean sus propias cuentas. No deben descargar los archivos de esta carpeta.

Si quieres conservar las cuentas que creaste localmente, hay que trasladar el respaldo completo de la base de datos y los adjuntos al disco del servidor. Sin esa migración, la web pública empieza con su propia base vacía.

SI ALGO SE TRABA

Qué revisar.

  • No abre en el equipo: vuelve a ejecutar el archivo de inicio y revisa data/servidor.log.
  • Google dice dominio no autorizado: añade el dominio exacto en Firebase. En tu equipo usa localhost.
  • No guarda en internet: revisa disco persistente y DATA_DIR.
  • Error de origen: comprueba que PUBLIC_URL coincide exactamente con la dirección que visitas.
  • No puedo grabar: permite el micrófono. La web pública necesita HTTPS.
